# 采购到货截单

主入口：采购单详情 → 到货单 → 申请到货单截单。采购单详情也支持选定批次撤回或终止整单剩余采购。入库单只提供跳转到货单的入口，原仓库取消接口也转入同一截单流程。

## 业务语义

- 单批撤回保留采购需求；待确认数量仍占用到货额度，其他未安排额度可继续创建到货单。
- 终止剩余采购先冻结整张采购单的新到货安排，逐批确认完毕后关闭剩余需求。部分失败不撤销已成功的处理，也不提前关闭整张采购。
- 原计划、实收、入账和截停数量分开保留；未收货取消后的到货状态为 6（已取消），部分实收关闭余量为 5（已关闭、部分收货）。正常收货完成仍为 4。入库单部分关闭状态为 7，不使用“作废”掩盖原实收。
- 新到货额度按每个 SKU 校验。截单未完成仍按原安排计入；截单完成后按原计划减截停量计入；常规最终短收按实际数量计入。所有变更沿用采购 → 到货 → 入库 → 仓库任务锁顺序。

## 仓库与库存

确认从未尝试下发的 PENDING 任务可以本地取消，并用任务状态和到货截单状态阻止延迟下发，不产生假的仓库日志。下发中、未知或存在历史尝试的任务先核对原任务。超时的取消只查询确认；明确拒绝取消须人工重试原申请。

`wms_connection.partial_inbound_cancel` 默认 0。仅在仓库确实支持且已验收部分收货关闭余量后开启；否则等待人工联系仓库，登记原仓库单号、凭证及逐行最终正品/次品实收。数量必须与系统已接收数量一致，存在差异须先补齐或核对回传。

仓库截停确认和到货额度释放是两个步骤。已接收的有效实收继续使用原 `WMS_RECEIPT_<明细ID>` 幂等键入账，失败时保留原额度。所有已接收实收确认入账后，才关闭到货余量；没有实收的部分不增减库存。

取消意图独立存于任务 `cancel_state`，正常实收回传不会擦除它。取消后新的实收回传在同一个采购锁事务中落入 `wms_inbound_receipt_review`，返回拒绝且不入账；精确重复的旧有效消息仍幂等确认。

人工可拒绝回传，或核实实收后确认。确认实收重新校验原 SKU、数量、批次以及每个 SKU 的采购安排额度，不能抢用已重新安排给其他批次的额度。确认成功后仅按实际新增实收量恢复占用并入账，不重新打开原仓库任务。

## 实现与运行

- `purchase_cutoff` / `purchase_cutoff_item`：原申请及逐批确认结果，包含申请人、原因、人工依据和待办时间。
- 新的即时处理复用公共 `ScopedWorkExecutor` 和显式公司延续上下文；采购审核、新回传及截单提交后定向唤醒对应任务。
- 后台补偿复用原入库扫描 `WmsInboundService.pollCompany`，无新增 Quartz 任务，也不改已有定时器开关或表达式。无即时执行容量时原持久化记录保留，等待补偿。
- 权限：`warehouse:poInfo:cutoff` 发起/重试，`warehouse:poInfo:cutoffReview` 登记仓库确认及处理冲突实收，原查询权限用于读取。
- 日志中心支持采购单号、到货单号和入库单号关联查询。原始接口结果与当前截单、实收记账结果分别展示。

安装：`python3 docker/local/configure_purchase_cutoff.py`，标准 WMS schema/runtime 安装也已接入。只增加字段、表、索引及权限，不回填历史单据或推断仓库能力。

测试：`docker/local/test_purchase_workspace.py` 包含 `PurchaseCutoffTest` 的并发、记账失败、取消未知、部分收货、终止整单及迟到实收等场景。`docker/local/verify_purchase_cutoff.py` 使用独立测试商品和本地 TEST 模拟仓库，保留验收单与截图，不扫描既有单据、不修改定时器。
