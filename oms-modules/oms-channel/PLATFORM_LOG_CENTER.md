# 平台交互日志中心

入口：渠道 → 平台交互日志（`/oms-channel/platformLogs`）。店铺、平台/业务订单、换货单、发货单和平台回传任务均跳转至此，业务任务处理记录仍保留在原业务页。

## 记录规范

- `channel_interaction_log` 增加类型、平台、环境、接口、请求/链路/业务请求编号、触发来源、HTTP 状态及结束时间。日志中心仅查询 `record_version=1`，不回填已有记录。
- `channel_interaction_payload` 单独存储受限脱敏快照；`channel_interaction_business_link` 保存类型化业务单号及索引。列表不读取正文、不解析业务 JSON。
- 业务操作为父记录；OAuth 换令牌、核验店铺等实际请求逐次记录。所有真实 TOP/OAuth 调用均经 `PlatformInteractionLog.call`，调用前提交记录，独立事务保存结果。线程上下文使用有作用域的恢复机制，不传播请求线程全部信息。
- `API` / `SIMULATION` / `OPERATION` / `CONFIG` 明确区分。现有发货网关仍仅模拟：新模拟提交/查询会记录于中心，绝不标成真实 HTTP 请求。推送库同步不是平台接口请求，未调用平台不创建接口成功记录。通知与后续售后类别预留，接入真实入口后按相同规范记录。
- 本次交互结果完成后不可覆盖；超时查询另起日志并关联原业务请求。HTTP 200 不代表业务成功，换货业务响应校验位于单次调用记录的边界内。
- 接口结果与当前业务状态分开。页面按页一次批量查询订单服务；失败显示未知，不改写原日志。当前状态会变化，原始请求响应快照不变化。

## 查询与权限

默认最近24小时，显式范围最多31天。完整单号或请求编号可查本单保存期内全部时间。每页默认50、最多100，按 `(create_time,id)` 游标翻页。单号通过关联索引精确定位；OMS 单号必要时由订单服务按公司解析别名。独立查询使用独立链路，只有同一待确认写操作的提交和查询共用业务请求编号。关联过多时要求缩小到换货单或发货单，不扫描原始报文。

- `channel:platform:log`：列表、统计、详情、链路、业务状态。
- `channel:platform:payload`：按需查看脱敏报文。
- 页面公司来自登录身份；内部模拟日志要求内部认证及明确公司，校验店铺归属，只允许已实现的模拟发货动作。
- 报文采用字段白名单、凭据字段拒绝、已知凭据值清除和个人信息脱敏。未知自由文本不记录。单字段512字符、数组50项、深度12层、正文64K字符上限，超限明确标注，不影响业务响应。凭据不存在“查看原文”权限。
- 日志页只读，重试、核对、重新提交从原业务单据操作。

## 保留期及部署

`oms.platform-log.summary-days` 默认90，`oms.platform-log.payload-days` 默认14，配置在渠道服务生效；报文保留期不超过摘要。每批至多删除2000份报文和1000条摘要，逐批提交；每家公司每次至多30秒或1000批，避免大事务，也能继续清理超过单批的积压。每天01:20由 ruoyi-job 的 `platformLogTask.purgeAll()` 分公司分批清理：只处理平台日志表，不修改订单、库存、售后或任务记录。

执行 `python3 docker/local/configure_platform_log_center.py` 安装表字段、索引、独立菜单和报文权限及清理任务，标准渠道配置脚本也已接入。部署 channel、order、job 及前端。无历史数据修复。

验证：`docker/local/test_channel_platform.py`、`docker/local/test_platform_log_order.py`、`node ruoyi-ui/tests/platform-log-center.cjs`，以及本地 TEST 店铺和模拟发货的页面验收。

## 业务入口与平台处理说明

日志页提供常用业务页签和中文业务动作（包括“回传换出物流”），接口英文名保留在高级筛选和详情中。默认自动识别完整单号并查询该单摘要保存期内全部时间；高级筛选仍可明确选择单号类型及手动时间。

`AUTO` 使用按公司隔离的精确单号及业务别名解析，不模糊扫描报文。发货单仅展开它自己的包裹、任务和所属换货单；单张换货单不扩散到同一原订单的所有换货。所有关联解析受300条上限保护。

换货详情顶部与按单号查询日志时复用“平台处理”卡片，说明无需回传、待审核/出库/包裹、待人工提交、请求待执行/待确认/失败、平台已确认等状态。当前业务状态独立于不可变接口结果；本地协商履约完成不等于通知平台成功。没有实际调用的业务仅展示说明，不创建接口日志。

`/platform/log-center/context` 是同一日志权限下的只读业务上下文，最多展示20张关联换货单；订单服务按批次聚合出库、包裹及运单数量，无逐单远程查询。业务说明查询失败单独提示，不伪造空记录或影响接口原始结果。

本轮页面验收：`docker/local/verify_platform_log_progress.py`（只读保留验收单，核对业务事实不变）。
