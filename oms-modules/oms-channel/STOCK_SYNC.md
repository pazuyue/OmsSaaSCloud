# 平台库存同步

入口：库存 → 平台库存同步。公司、店铺、OMS SKU 唯一确定同步组；组内最多20个链接。平台商品ID和SKU ID使用字符串，无规格SKU填0，同一平台目标只能有一个库存来源。

## 数量与来源

普通商品和实物套装读取当前渠道可售；虚拟套装按发布组成、组件渠道额度、店铺允许仓和同虚拟仓完整套数保守计算。福袋未接通选品与可售计算前明确阻断，不把错误转换成0。

总预算=max(0,可售-安全库存)，再取组上限；扣除停用链接仍在平台销售的数量后，按权重分配给活动链接。整数余量按小数余量及链接ID稳定分配。链接上限截留的数量不自动转投其他链接。链接上限是当前可售上限，不是活动累计销售限额。

读取库存服务的快照不会新增或扣减物理库存，但会刷新既有渠道可售投影。待订单预占、分仓、实际出库继续走原台账。

## 执行与恢复

手动提交保存PENDING，统一由platformStockSyncTask.scanAll()处理；自动组每60秒重算。任务接入ruoyi-job，默认每分钟扫描。每公司单轮最多20组、45秒预算（完成当前组后退出），组租约180秒并在外部调用前续租，无新增MQ。重复提交合并，执行前重算，不重发旧执行快照。

使用已授权店铺，复用凭据加密、绑定验证和平台操作租约。真实调用：

- taobao.inventory.mode.query：只接受普通库存模式1；其他模式明确报错。
- taobao.item.seller.get：验证数字ID映射并观测库存，不将观测值当成OMS库存来源。
- tmall.item.quantity.update：全量设置绝对目标，严格核对quantity_update_result。
- taobao.trades.sold.get：补高前核对待付款、待发货交易，按关联的商品与SKU过滤；单状态超过100单或不完整时暂停补高。

先完成所有减少，再执行增加；减少失败或结果不明停止本组后续增加。每次写入前重新读取OMS库存，对增加再次读取平台库存，观测变化则等待下一轮。平台交易字段、OMS平台明细的规格/数量/匹配结果/需求登记、订单更新时间必须对应；拉单错误、未启用或游标滞后超过120秒暂停补高，但仍允许减少。预付款等未纳入当前核对范围的订单不推断为已覆盖。

周期性同步与平台成交之间没有跨系统原子事务，不能承诺零超卖。正式店铺应先验证接口权限、库存模式和活动限制，并配合安全库存。

确认写入成功后另行查询平台当前数量；查询失败时保留提交成功并将观测值置空，不重发已确认写入。

每个链接写入前持久化UNKNOWN及目标；超时不盲重发。下轮查询与原目标一致可确认，否则需人工“核对当前结果”（保留原因，并等待原请求超时窗口）。关闭同步不清零，停用链接仍扣投放预算；“清零并退出”成功后才释放额度。尚未观测或提交的错误映射可以修改/移除，已执行映射不能直接覆盖或删除。

所有配置、查询、写入、人工核对接入平台交互日志的STOCK分类。模拟模式来自绑定应用的服务端配置，页面明确标记，不能由请求指定。保留最近20轮执行摘要，报文遵循现有平台日志保留期。

## 部署及验收

- python3 docker/local/configure_stock_sync.py：新增表、菜单权限、Quartz任务，不回填历史单据。
- python3 docker/local/test_stock_sync.py：隔离MySQL回归；包含多链接分配、失败/未知结果、库存口径、套装同仓及订单接入保护。
- python docker/local/verify_stock_sync.py：保留独立模拟店铺和三链接测试组；54/27/9、停用曝光、清零退出、拉单滞后阻断增加、实物库存不变及浏览器验收。
